# AI 规格书生成：需要接入多大的模型？（AI_SPEC_MODEL）

> 问题：Snap2Edit 的「上传图片 → 生成 spec」后台，接入多大参数量的视觉语言模型（VLM），
> 才能精准实现图片的原样复刻？
>
> 结论先行：**精准复刻 ≠ 堆模型参数，而是「模型上限 × 流程下限」的乘积。**
> - 最小可用：**10B 级轻量 VLM**（如 GLM-4.6V-Flash 9B / Qwen3-VL-8B 档）——可产出结构正确的
>   草案 spec，配合本文的重试与规范化管线达到可用精度；
> - 推荐配置：**100B 级 MoE 旗舰**（总参 100B+/激活 10–30B，如 GLM-4.6V 106B·12B 激活、
>   Qwen3-VL-235B 档）——单遍直出高密度图表规格；
> - 精度的最后一公里永远由 **Snap2Edit 四道校验门 + 规范化管线**兜底，而非模型本身。
>
> 版本：2026-11-03 · 作者：Snap2Edit Contributors

## 1. 任务拆解：复刻对模型的四个能力要求

| # | 能力 | 难点 | 对参数量的敏感度 |
|---|------|------|------------------|
| 1 | **精确视觉定位**（grounding） | 输出元素级坐标 x,y,w,h，像素级对齐 | 高——小模型坐标漂移明显，是复刻失败的第一原因 |
| 2 | **密集文字 OCR 转录** | 中文信息图文字逐字转录，一条不能丢 | 高——7B 以下长文本漏录/改写率显著上升 |
| 3 | **长结构化输出** | 一张复杂图 ≈ 100+ 元素的 JSON（4–8K tokens） | 中——要求输出稳定不截断、转义不失误 |
| 4 | **色彩/层级感知** | 主色取样、卡片分区、遮挡关系 | 中——可由客户端取色 + 规范化补偿 |

另有两个非参数量因素同样关键：**高分辨率输入**（tile 切分策略，决定小字是否可读）
与**结构化输出训练**（JSON mode / 原生工具调用，决定转义与格式稳定性）。

## 2. 模型分档与复刻精度预期（2026 年格局）

| 档位 | 代表模型（参数量） | 单遍复刻能力 | 适用场景 |
|------|--------------------|--------------|----------|
| 轻量级 | GLM-4.6V-Flash（9B）、Qwen3-VL-8B | 布局骨架正确；密集小字有漏录；坐标 ±15–30px 漂移 | 骨架草稿、简单卡片图；**必须**配重试+规范化 |
| 中量级 | 30B 级 dense / 同档 MoE | 常规图表可复刻；复杂信息图文字偶有截断 | 日常图表批量处理，性价比档 |
| **旗舰级（推荐）** | **GLM-4.6V（106B MoE，激活 12B）**、Qwen3-VL-235B、闭源 GPT-5V / Gemini 2.5 Pro 档 | 高密度信息图单遍直出：全部文字转录 + 坐标 ±8px 内 | **Snap2Edit 生产默认档** |
| 本项目实测 | glm-5v-turbo（Z.ai 端点，GLM-5V 系） | 1280×720 复杂方法论图：**一遍过校验**，129 元素/92 文本，四道门全绿 | 已接入本工作台 |

参考基准：GLM-4.6V 在「看图写 React」的 Flame-React-Eval 上得 86.3，反超参数量
近一倍的 Qwen3-VL-235B（73.8）；两者均为 MIT/开源可商用协议。GLM-4.6V 官方将
「前端复刻：从 UI 截图重建像素级 HTML/CSS」列为核心能力——与本任务同构。

## 3. 为什么「流程」比「参数量」更决定下限

本次实测中，即使旗舰模型也会出现四类输出事故，**全部由管线确定性修复，模型无需重训**：

| 输出事故 | 管线修复（`web/lib/spec.ts`） |
|----------|------------------------------|
| YAML 引号未闭合（初版管线两次失败的主因） | 改为 **VLM 只输出 JSON**，服务端确定性序列化 YAML |
| 长描述写入元素时被截短 | `normalizeSpec` 按 texts 清单**前缀回填** |
| 多行文字挤在一个 text 值 | 按 `\n` 拆分为独立单行元素（y 递增） |
| `"16:9"` 无引号被 PyYAML 读成六十进制整数 969 | 双引号风格强制序列化（YAML 1.1/1.2 跨解析器陷阱） |

剩余的坐标误差（±8px 量级）由门 3（PIL 实测防溢出）与人工微调兜底——
这正是 PRD 中「模型提议、程序验证」的分工：**模型负责看懂，流程负责做对。**

## 4. 选型建议（按部署方式）

| 部署方式 | 建议 | 说明 |
|----------|------|------|
| API 接入（推荐起步） | Z.ai 端点 GLM-5V/GLM-4.6V 系 | GLM-4.6V 满血版公开价约 ¥1/百万输入 tokens、¥3/百万输出 tokens；单张图 spec 成本约 **¥0.02–0.05**（估算：图 ~2K + 提示词 ~1.5K 输入，输出 ~5K tokens）；Flash 档免费 |
| 自部署（低成本） | GLM-4.6V-Flash（9B）或 Qwen3-VL-8B | 单卡可跑；务必启用本文的重试 + 规范化管线 |
| 自部署（高精度） | GLM-4.6V 106B（FP8） | 需多卡集群；激活参数仅 12B，推理成本低于同档 dense |

工作台已支持 `SNAP2EDIT_VISION_MODEL` 环境变量切换模型，便于实测对比。

## 5. 后续精度增强路线（对应 PRD v2.0）

1. **裁剪放大二次精修**：对门 3/门 4 报告的溢出区域裁剪原图局部，二次询问模型修正坐标；
2. **程序化取色注入**：用 OpenCV/水滴采样替代模型目测色值（已由客户端 canvas 取色起步）；
3. **渲染反馈闭环**：把 `snap2edit check` 报告自动回询模型迭代（Web 侧已具备重试框架）；
4. **组件库先验**：v0.5 组件库落地后，模型只做「选组件 + 填参数」，进一步压缩坐标误差。
